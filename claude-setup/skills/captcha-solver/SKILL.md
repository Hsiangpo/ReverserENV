# Captcha Solver

验证码链路的目标是：`识别协议与分支 → 完成当前验证状态 → 服务端二次校验 → 业务消费凭证`。
只有当前 challenge 确实需要图片或轨迹时，才进入图像识别与行为数据处理。
优先交付 Python + `requests` 的协议实现；依赖原 SDK、oracle 或特定 transport 时，必须如实保留该边界。

仅处理已获授权的目标；不用于账号滥用、凭据窃取、绕过访问控制、批量隐蔽采集或攻击生产反滥用系统。

## 职责边界

本 Skill 负责：

- 滑块、点选、语义宫格、语序、算术验证码的识别与坐标转换。
- 样本支持的轨迹、点击顺序、行为时序，以及当前协议要求的指纹数据组装。
- 验证码提交自身使用的 AES、DES、XOR、自定义 Base64、gzip 或 PoW。
- 验证码初始化、按需取图、verify、服务端二次校验和业务接口消费的完整链路。
- 无感 token、评分结果、测试模式与容灾返回的来源、时效和验收边界。

转交边界：

- 加密类型尚未实证、需要抓流量或定位函数：`web-reverse-master`。
- 非验证码业务参数的签名或加密：`param-encryptor`。
- 验证码 SDK 必须在 Node.js 中运行且缺浏览器 API：`env-patcher`。
- 验证码 JS 存在字符串表、dispatcher 或控制流平坦化：`ast-deobfuscation`。

不要用 Selenium、Playwright 或 Puppeteer 代替协议实现。浏览器、CDP、真实浏览器交互或第三方 transport
只能用于取证、动态 oracle，或已授权并明示的有限依赖；最终产物必须标明仍存在的依赖。

## 不变量

- 先识别验证码类型、服务商、协议版本和当前分支；不同服务商不得套用同一组密钥或轨迹。
- 有真实初始化/提交抓包和至少一组 input→output 对后再还原；加密算法、Key、IV、Mode 不得猜测。
- 几何滑块本地识别优先；语义、宫格、语序和自由点选可复用本 Skill 的 `scripts/mmcaptcha/`，云码仅作兜底。持续交付时把该包复制进站点 `src/`，不得依赖仓库外或未跟踪模块。
- 轨迹和时序只按同版本真实样本建模；不默认添加过冲、回拉、Y 抖动、随机采样或固定速度。旧样本的常量只代表其目标与版本，必须重新对拍。
- 分别记录图片、session、token、动态 key 和 ticket 的生命周期；不得将一个厂商的有效期或一次性规则套到全部字段。绑定条件区分“官方支持”和“目标已启用”。
- 识别通过、HTTP 200、外层 success、SDK 容错返回或测试 key 通过不等于真实验证成功。供应商校验与业务接受分别留证；容灾放行不能计入正常验证成功率。
- 商户服务端 secret/sign_token、浏览器生成参数、供应商返回 token 分开谱系；公开服务端 HMAC 公式不能证明客户端验证码算法已还原。
- 完整协议交付沿用 master 的 [项目谱系契约](../web-reverse-master/references/16-lineage-contract.md) 与原字段/请求 ID；初始化、提交、二次验证和业务消费分别关联同轮证据。未知 TTL/绑定、未取得的后端判官保留缺口，不能用前端成功回填通过；工具的通用业务记录不替代本 Skill 的正常验证/测试/容灾分支验收。

## 先选择验证分支

输入实际 SDK、初始化与提交样本，记录产品名、客户端版本、API/schema 版本、区域与当前模式。
品牌、路径片段或旧样本只能作线索，不能直接确认版本或算法。

| 当前链路 | 工作重点 | 不应自动执行 |
|---|---|---|
| 无感 / passive token | 初始化、采集或判定依赖、token 发行、后端验证、业务消费 | 下载图片、生成滑块轨迹 |
| 有交互 challenge | 图像/题意/坐标、要求的轨迹、提交参数、二次校验 | 故意失败以强制触发某个历史分支 |
| 评分 / risk verdict | action/scene、score 方向与范围、reason、阈值和业务决策 | 将一个厂商的高分含义套到另一个厂商 |
| 托管挑战 / clearance | 确定 token、cookie、clearance 与访问路径、会话、时效的关系 | 将 cookie 出现当业务登录或授权成功 |

Invisible 可能只是隐藏 checkbox，仍会触发题目；同一产品也可能在多个分支之间升级或回退。
混合 Bot/挑战/业务策略、未知发行算法或不清楚消费者时，先交 `web-reverse-master` 定位。

## 按当前缺口执行

### 1. 固定样本、状态与消费者

尚无真实初始化/提交抓包或 input→output 样本时，先补证据，不猜测编码。
记录应用/sitekey/scene/action、session、初始化标识、时间来源、验证区域、供应商 verify
和业务消费接口；只请求已授权的必要样本。纯本地分析使用既有资产，不强制线上复测。

### 2. 有题目时才识别与转换坐标

保存当前 challenge 的背景图、滑块图、提示图、原始尺寸及坐标元数据。
图片为空、被打乱或需 WASM 解码时，先恢复可验证像素，不把空图送入识别器。

- 几何滑块：先用 OpenCV；低置信度再走云码或内置 `mmcaptcha.slider_gap`。
- 语义/宫格/语序/点选：可用内置 `scripts/mmcaptcha/`；当前选格由模型给出，需确定性“和/或/不含”时由调用方对逐格标签做集合运算，不能宣称本包已有该判定器。
- 算术：使用 ddddocr，并对 OCR 表达式做白名单清洗。

检查点：结果必须落在图片与滑块尺寸允许的范围；坐标系缩放、打乱图恢复和 CSS 偏移须分别验证。
异常结果直接丢弃并重新取图，不得提交探测。

### 3. 协议要求时才生成轨迹

输入目标坐标和协议要求，输出 `[[x,y,t], ...]` 或厂商指定结构。
按样本确认坐标原点、单位、缩放、事件类型、时钟、采样、终点和序列化；不以“看起来像人”替代验证。
行为数据的采样、单位和事件顺序见识别参考；该参考不提供无目标依据的随机行为模板。

检查点：终点、持续时间、采样间隔、Y 坐标、过冲回拉及协议字段必须与浏览器样本同量纲。

### 4. 生成当前分支所需参数

将当前分支的行为数据、坐标和会话数据送入已实证算法。
字段序列化、字节编码、会话密钥和证明条件按 [references/encryption-and-providers.md](references/encryption-and-providers.md) 核对。

检查点：字段谱系、编码和版本须与样本一致；长度仅是排错线索，不设通用 ±10% 成功门槛。
算法复现需字段级和任意输入字节对拍；不得将其他版本的固定密钥字典替代当前会话下发值。
官方要求透传的 token/密封载荷按原字节保留，不能用硬编码样例或修改载荷代替生成过程。

### 5. 记录供应商验证与二次校验

使用同一会话、UA、cookie、IP 与必要 transport 调用 verify，解析 ticket、validate、pass_token、
randstr 或厂商错误码。记录提交明文摘要、密文长度、HTTP 状态和解码后的业务响应。

检查点：分别记录 HTTP 状态、API 外层状态、内部验证结果、score/reason、测试与容灾标记。
错误码先查当前版本官方语义，再提出区分性实验，不能只凭一个码确定 TLS、行为或频率根因。
后端二次校验需要商户凭据时，仅在已授权且凭据可用的集成中执行；拿不到验证结果应标未验证，不能补造。

### 6. 用业务接口消费凭证

立即携带凭证调用目标业务接口，记录服务端业务语义。
只有供应商正常校验通过且业务接口接受凭证，才可称该轮正常验证闭环；同时记录时效和绑定。
若实际是容灾或测试策略放行，单列为该策略下的业务结果，不能声称真实 challenge 已解。
只观察到前端 token/clearance、没有后端判官时，交付到已证层级即可，明确剩余缺口。

## 停止条件

- ticket 无效、过期或已消费：先核对发行、传输、校验与消费时间；不得重放旧 token。需要新样本时按当前协议重新初始化，不将最多次数当必须重试次数。
- 同一请求同字节总计最多 3 次（含首次）；出现漂移/随量降级立即停止重发。同接口第 3 次同类失败即停线上实验，保留响应并转证据链归因。
- 识别坐标连续异常：停止提交，检查图片恢复、尺寸与坐标转换。
- 密文长度或字段集合不符：停止提交，回到算法/Key/IV/Mode 对拍。
- 遇 403/429 或供应商内部错误，先保存原始响应和当前状态，按 [references/integration-and-failures.md](references/integration-and-failures.md) 设计区分性实验；不自动换 transport、加并发或重复提交。
- 三次新会话仍失败：检查时间同步、session 生命周期、一次性资源与环境绑定，输出未闭合字段和下一个区分性实验。

## 产出与验收

每次交付至少包含：

1. 当前分支：无感、交互、评分或托管挑战；有题目才附识别结果、原图尺寸与坐标系。
2. 轨迹数据：协议要求时附完整轨迹及终点、持续时间、采样规则；否则标不适用。
3. 加密参数：字段来源、算法、Key/IV 来源、编码和生命周期。
4. 服务端验证：脱敏的 token 来源、二次校验结果、内外层状态、score 与测试/容灾标记。
5. 业务验收：凭证被哪一个业务接口接受、对应业务语义，以及是否依赖放行策略。
6. 时效和边界：各步耗时、session/票据有效期、版本、transport/oracle 依赖与未闭合字段。

性能和成功率只在已声明版本、会话、模式与时间窗口内统计；不使用跨厂商统一的 5 秒成功判据。
