# 验证码参数、编码与状态边界

> 读取条件：验证码内置算法已实证，需要确定输入、编码、会话密钥、运行依赖和字节对拍。
> 未知函数、WASM、VM 或环境缺口先由 `web-reverse-master` 定位；非验证码参数交 `param-encryptor`。
> 后端商户签名、token 消费和容灾状态见 [verification-and-fallback.md](verification-and-fallback.md)。

## 参数谱系

| 类型 | 必须记录 | 不可替代为 |
|---|---|---|
| 会话下发 key/token/seed | 初始化响应字段、编码、作用域、刷新条件 | 旧版本固定 key 或捕获样例 |
| 客户端本地派生 | 当前源码入口、输入、字节序列化、任意输入对拍 | 只有同样例输出的拟合函数 |
| 设备/行为采集 | 实际采集事件、环境、时间源、等待条件、消费者 | 多个样本未变就当永久常量 |
| 商户服务端签名 | 官方验证接口、授权凭据、签名消息与版本 | 浏览器验证码加密“已经还原” |
| 原 SDK / WASM / VM 输出 | 资产 URL/hash、入口、运行时、异步完成状态 | 独立算法的纯算完成证明 |

只有样本显示某一步下发新值时才更新相应状态；刷新初始化标识后不得混用旧 key、旧 proof 和旧图片。
同一 SDK 多次调用 encrypt 时，应沿实际网络发送的那次调用追踪输入与返回值，不按调用序号或密文长度挑选。

## 字节层检查

- **文本与二进制**：区分 UTF-8、Latin-1、JS 二进制字符串和原始 bytes；不能把二进制响应先转文本再还原。
  CDP 的 postData 必须先确定捕获形式，不能对所有字符串统一按 UTF-8 编码。
- **URL 编码**：记录 SDK 返回值是否已 percent-encode、HTTP 库是否再次 form-encode；核对线上原字节，
  不盲目追加 `quote` 或 `unquote`。序列化前值与实际发送值分别保存脱敏摘要。
- **JSON/MessagePack**：保留对象/数组、字符串/数值、浮点精度、嵌套 JSON 字符串及字段顺序要求；
  不用正则全局替换时间戳或将所有二进制载荷视为 JSON。
- **Base64/自定义字表**：确认标准或 URL-safe 字母表、padding、分组/位掩码和尾部拼接；
  相同外观不证明是标准 Base64，旧厂商字符表不可跨版本使用。
- **压缩/混合编码**：记录压缩→XOR→前缀等实际顺序、gzip 元数据/时间、字节索引回绕和 Content-Type；
  解密后能解析只是格式证据，仍要与独立 oracle 对拍。
- **分块加密**：确认 Key/IV 是原字节、hex 文本还是解码值，确认模式、padding、块大小、认证标签与拼接；
  零填充在“恰好整块”时是否追加一块必须对拍，不能凭库默认值选择。

## PoW 与执行证明

当前协议确有证明字段时，分别确认挑战来源、完整目标、比较方式（相等/前缀/阈值）、nonce 编码、
消息拼接、耗时单位、一次性消费和会话绑定。不默认某厂商始终使用 MD5、固定分隔符或同一 PoW。
由原 VM/SDK 计算的 proof 要标运行依赖；有 proof、token 或固定长度不等于供应商/业务已接受。

## 状态与归因

- 设备采集若异步完成，记录完成事件/返回值与调用时序；不靠固定 sleep 假设数据已齐。
- 验证码、指纹、会话 cookie 与 HTTP 请求中的环境字段只沿同一真实上下文关联；采样快照标为 fixture。
- 图片或响应可能一次性消费；需要取证时保存首次响应，空响应先检查是否已消费，不反复抓取。
- transport 变化后结果不同，应排除 headers、cookie、编码、时序和会话差异，再判断是否涉及网络指纹；
  单个 403/内部错误码不足以推出 TLS 或某算法根因。
- 图像识别、编码往返、生成密文、供应商正常校验与业务接受分别留证；其中一层完成不补写其他层。

不保留跨版本硬编码密钥、固定字段数量、固定轨迹速度或人为触发失败的通用配方。
