# Darwin Skill

## 定位

本 Skill 只维护其他 Skill 的发现、边界、工作流、资源和行为质量。普通领域任务不自动触发它，也不借“优化”扩展用户选择的产品、仓库、权限或外部动作。

优先精简：保留会改变决策的知识、真实约束和失败恢复；删除通用常识、宣传、重复案例、虚构成功率和为了评分增加的章节。

## 9 维评估

| # | 维度 | 检查点 |
|---|---|---|
| 1 | Frontmatter | name/description 合法，做什么与何时用清晰，触发不泛化 |
| 2 | 边界与路由 | 适用/排除明确，不抢相邻 Skill 职责 |
| 3 | 工作流 | 输入、输出、决策和判官可执行 |
| 4 | 失败编码 | 有可判定的触发→一线→仍失败 |
| 5 | 具体性 | 高风险不变量精确；普通步骤不过度僵化 |
| 6 | 资源整合 | scripts/references/assets 可达且按需读取 |
| 7 | 精简与架构 | 不重复、不堆案例，渐进披露合理 |
| 8 | 行为实测 | 带 Skill 相比 baseline 是否实际改善结果 |
| 9 | 反例与恢复 | 关键不要做什么、停止条件和回滚清晰 |

各维度按 1–10 评分；若需要百分制，可使用项目既有权重并保留原始分。分数只作摘要，不能替代行为证据。

## 评估模式

- `full_test`：独立评审者用相同 prompt 比较 with-skill 与 baseline，并检查实际产物/动作。
- `dry_run`：只做静态推演；必须标注，不能声称行为质量已提升。

复杂、跨运行时或高风险 Skill 应使用独立 judge；不得由同一上下文改完立即自评。judge 只接收现实 prompt、待评 Skill 和必要原始材料，不提供期望结论。

## 工作流

### 1. 固定范围与工作树

1. 确认真源、镜像、目标 Skill 列表和不允许触碰的目录；
2. 记录分支、`git status --short`、目标文件 hash/行数/BOM 和现有测试；
3. 读取目标 `SKILL.md` 全文及它明确要求的相关资源；
4. 目标已有用户改动时只编辑可定位 hunk；禁止 stash/reset/checkout 丢弃或整树覆盖。

若用户已批准一轮“全量优化并继续”，可把它当本轮批量人审检查点；仍需逐项记录、验证和报告。

### 2. 设计或复用 test prompts

每个 Skill 使用 2–3 个现实请求：

- 典型 happy path；
- 一个会触发失败恢复或边界判断的场景；
- 必要时一个相邻 Skill 路由/高风险场景。

保存在该 Skill 的 `test-prompts.json`。已有 prompt 先核对是否仍匹配当前职责；不要用标题/固定词句匹配作为“行为测试”。

### 3. 建立基线

对每个 Skill：

1. 跑 frontmatter/路径/BOM/runtime 污染等静态检查；
2. 按 9 维记录分数和证据；
3. 用 test prompts 获取 with-skill/baseline 行为；
4. 标明 full_test/dry_run、最弱维度和真实失败；
5. 在修改前保存测试命令与输出。

无法运行的维度保持“未验证”，不能填造分数。runtime-specific 路径若是仓库明确的真源/镜像契约，不算通用性缺陷；只有错误地声称该 Skill 仅属于某 runtime 才算漂移。

### 4. 单变量改进

每轮只解决一个可归因问题块；相关的工作流/失败/恢复不变量可作为一个完整问题块一起修复。

优先级：

1. 假成功、越权、破坏恢复、错误工具契约；
2. 发现/路由错误和职责重叠；
3. 行为测试暴露的失败；
4. 缺失的失败分支或验收门；
5. 重复、过大和低价值内容。

不要因某维度分低就把别的 Skill 内容复制进来。修改后的正文不应无理由膨胀；若功能不变，优先缩短。

### 5. 棘轮验证

1. 重跑与基线相同的静态和行为测试；
2. 新/改脚本运行语法、单元和关键契约测试；
3. 独立 judge 复核相同 prompts；
4. 比较副作用、文件体积、路由、权限和回滚能力；
5. 只有证据显示不退步且目标问题已改善时保留。

没有改善或发生回归：只反向应用本轮 hunk。目标文件干净且已有独立 commit 时才用 `git revert`；禁止 `git reset --hard`。

连续两轮只有微小措辞变化、没有行为改善时停止；不要为凑轮数继续堆内容。

### 6. 汇总

报告至少包含：

- 改了哪些真源和为什么；
- 改前/改后行数；
- 静态测试、行为评审、脚本测试分别的结果；
- full_test/dry_run 比例；
- 保留/回滚决定、未验证项和镜像同步状态。

本仓库维护结果统一追加到 `docs/SKILLS_MCP_RULES_MAINTENANCE.md`，保留既有格式；旧展示包与两份不同的 `results.tsv` 已归档，不再作为当前评分证据。只有用户明确要求才生成结果卡片、提交代码、更新记忆或修改外部/全局配置。

## 异常恢复

| 触发 | 一线处理 | 仍失败 |
|---|---|---|
| 不在 Git 仓库 | 保存目标文件 hash 与可恢复副本 | 只做静态评审，先报告 |
| test prompts 缺失 | 建最小 prompt 文件并说明来源；结果记入项目维护日志 | 无法设计现实 prompt 时不评分 dim8 |
| judge 超时/输出不完整 | 相同输入重跑一次 | 标 `dry_run`，不报行为提升 |
| 目标与用户改动重叠 | 缩小到独立 hunk | 停该文件，不覆盖 |
| 同步/镜像失败 | 从真源重试一次并核对 hash | 停止，禁止手修派生副本 |
| 测试需要外部写入/高成本 | 保持离线夹具 | 需要新权限时先交用户决定 |

## 不要做

1. 不跳过 baseline/test prompts 就评分。
2. 不同一上下文自改自评并声称提升。
3. 不用 dry-run 分数冒充 full-test。
4. 不为评分加入冗余 checklist、案例、emoji 或绝对化措辞。
5. 不改变 Skill 核心用途、用户授权边界或无关配置。
6. 不静默跳过异常，不在脏树使用 stash/reset/整文件恢复。
