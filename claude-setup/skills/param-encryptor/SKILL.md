# Param Encryptor

把已经定位并有真实样本的签名或加密逻辑，复现为可验证、可集成的协议代码。核心判官是字节级 oracle 对拍和服务端业务语义，不是“看起来像某算法”或仅 HTTP 200。

仅处理已获授权的目标；不用于账号滥用、凭据窃取、绕过访问控制、批量隐蔽采集或攻击生产反滥用系统。

## 适用边界

- 已知目标字段、算法入口、输入和输出样本时使用本 Skill。
- 算法尚未知、需要抓包、搜索源码、Hook 或调用栈定位时，转 `web-reverse-master`。
- 验证码提交流程里的 AES、DES、XOR 和轨迹加密由 `captcha-solver` 负责。
- 原 SDK 只能在 Node.js 浏览器环境运行时，配合 `env-patcher`；被混淆的入口先交 `ast-deobfuscation`。
- `x-s` 等字段的执行路径由当前入口证据确定；实际使用 CDP/浏览器 oracle 时明示依赖，不能按字段名强制采用历史路径。Press & Hold、挑战票据或未知发行链交 `web-reverse-master`。
- 只使用当前会话实际提供的工具，不假设某个 MCP 可用。

## 开始前的证据门槛

至少拿到：

1. 目标参数及其最终序列化位置（header、query、body 或 cookie）。
2. 加密入口的文件、行号或调用栈，以及算法参数来源。
3. 至少 3 组真实 `input -> output` 样本，覆盖普通、空值或边界输入。
4. 下游判官和成功标准，例如 oracle 字节一致或服务端返回的业务语义。
5. 已获确认的实现方案；遵守仓库 Phase 3 Plan 门禁。

缺真实样本时先采集，不得空手猜实现。入口未定位时停止本 Skill，回到分析流程。

## 先做 ①②③ 分类

每个动态字段单独归类，嵌套对象不得整体笼统标成“签名”。

| 类别 | 判定 | 实现方式 |
|---|---|---|
| ① 客户端纯算 | HMAC、MD5、AES、RSA、白盒、VMP 等算法在客户端 | 复现算法并对拍；VMP 只影响成本，不改变可行性 |
| ② 可采浏览器指纹 | browser_id、Canvas、WebGL、Audio 等浏览器态 | 明示采集来源、生命周期和绑定，再作为算法输入 |
| ③ 服务端下发透传 | token、salt、公钥、`x-kpsdk-ct`、register key 等 | 调上游接口获取并记录刷新方式、时效与绑定 |

打上游拿到 ③ 再喂给下游仍可属于纯协议，但不是“完全离线纯算”。必须由真实浏览器渲染、可信执行或服务端一次性状态提供的值可能构成外部边界，但必须由对照实验确认，不能凭字段外观下结论。

## 执行流程

1. 建参数谱系：为每个字段记录来源、算法、精确输入、序列化、生命周期/绑定和单变量验证。
2. 选择配方：只读取当前算法所需的 reference，不默认加载所有配方。
3. 固定样本：将时间、随机数、nonce、key 和上游 token 注入为可重放 fixture。
4. 实现最小 signer：先验证单个函数，再组装最终字段，最后接入 Python 请求脚本。
5. 对拍：逐字节比较中间值与最终值；随机算法还要固定熵源或验证解密、布局和长度不变量。
6. 端到端验证：使用新会话/新输入，并保存解码后的业务结果和失败响应。

## 参数谱系模板

| 字段 | 来源 | 生成算法/依赖 | 生命周期与绑定 | 单变量验证 |
|---|---|---|---|---|
| `sign` | 本地生成 | 精确原始字节、算法、key/盐 | 单次请求或时间窗 | 固定输入与 oracle 对拍 |
| `token` | 服务端下发 | 上游接口与响应路径 | TTL、cookie、账号/session | 过期与刷新实验 |
| `deviceId` | 设备态 | 采集位置或派生式 | 设备、安装、账号 | 换值后比较业务语义 |

嵌套密钥、常量、header、query 和 body 字段均逐行填写；“来自抓包”不算来源，必须追到静态常量、本地生成、服务端下发或派生关系之一。

该表是阅读摘要。完整协议任务使用 master 的 [项目谱系契约](../web-reverse-master/references/16-lineage-contract.md)，把精确字段路径、producer/consumer、字节变换、证据 ID、实现函数和未知项填入同一 `lineage.json`；本 Skill 回填原字段 ID，不另起一份会漂移的谱系。单函数算法分析可以只保留对应字段卡及真实对拍，不为使用 HAR 检查器伪造请求。

## 实现约束

- 主入口使用 Python 协议请求；标准算法优先 `hashlib` / `pycryptodome` 等项目 venv 依赖。
- 自定义 SDK、WASM 或 VM 的最小可信复用可放 `signer.js`，由 Python `subprocess` 调用；明确它是否仍依赖原始 SDK。
- 生产路径不得依赖 Selenium、Playwright 或页面自动化。调试 oracle 只能用于取证和对拍。
- 精确保留输入顺序、JSON 空格/转义、字符编码、大小写、padding、输出编码和时间戳精度。
- 动态 key、salt、token、公钥不得伪装成常量；从上游获取或通过配置显式注入。
- 设备态和会话态不能跨账号、IP 或 session 盲目复用；记录其绑定边界。
- 依赖只加到项目环境；不要调用全局 Python。

## 对拍与验收

- 至少 3 组非样例输入与真实 oracle 对拍，最终字节必须一致；只命中一组 fixture 不算还原。
- 对称算法逐项核对 `Key / IV(or nonce) / Mode / Padding / AAD / tag位置 / 输出编码`。
- RSA 核对公钥来源、位数、padding、分段方式及 Base64/hex；信封加密同时核对字节布局。
- 哈希签名核对原始字节串、字段排序、分隔符、盐、编码和自定义 padding。
- assembler 对每段保存中间值，验证段数、顺序、依赖字段和生命周期。
- 服务端验收必须记录解码后的业务效果；HTTP 200、响应可解析或长度正确不能单独证明成功。
- 分开报告“算法字节一致”和“业务请求通过”，不得用其中之一替代另一个。

## 失败与停止条件

- 本地与 oracle 不一致：立即停止集成，从第一处不同的中间字节反查，不得提交近似值。
- 标准 MD5/SHA 与 SDK 不同：先验证输入类型、编码、自定义 padding/盐；有证据后才复用原 SDK。
- AES 乱码或密文不同：逐一做单变量实验，不批量更换 Key/IV/Mode/Padding。
- 字节对拍已通过但服务端拒绝：冻结算法，转查 ③ 字段时效、请求依赖序、cookie、TLS/UA、header 与会话绑定。
- 同一请求同字节最多总计 3 次（含首次）；任一次出现漂移或随量降级就停止同字节重发，按归因程序设计区分性实验。
- `403`、`do:null`、`202/400` 或 `5014` 不是天然的“算法错”或“风控”证据；按实际响应、字节差异和协议状态设计区分实验。
- VMP/白盒复杂不能证明不可复现。按当前实现如实声明已存在的 oracle/上游依赖；若要声称依赖不可替代，另需调用链和对照证据，不能从字段名或拒绝响应推断。

## 禁止误报

- 不把抓包中的动态值硬编码后宣称已还原。
- 不把服务端签发的 token 当成本地加密算法硬撕。
- 不在缺少三组样本或参数谱系有空洞时宣称“纯算完成”。
- 已对拍的输出若仍依赖未知 key、重放 token 或未定位的环境值，继续列为依赖缺口；服务端不透明 token 的研究边界是可复核的发行/存储/消费/刷新过程，不编造服务端内部算法。
- 不因请求拒绝就随机改密钥、随机补 header 或轮换多个账号/IP。
- 不把调用真实浏览器、外部运行时或在线接口的实现标成离线纯算。

## 交付物

交付应自包含，并至少包括：

- `signer.py`；只有确有必要时增加 `signer.js`，由 Python 主脚本调用。
- 可执行的请求入口、项目内依赖说明和不少于 3 组 fixture/oracle 校验。
- 参数谱系表：字段、来源、生成算法、生命周期与绑定、单变量验证。
- 算法证据：入口位置、输入输出、中间值、字节对拍结果和端到端业务结果。
- 边界声明：目标/SDK 版本、工作条件、失效表现、未逆字段、上游或 oracle 依赖。

只有谱系零空洞、任意输入对拍通过且动态字段实验落定，才可称“还原完成”。否则按解析型、绕过型或 oracle/止损型如实标注。
