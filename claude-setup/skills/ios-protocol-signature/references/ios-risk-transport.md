# iOS 风控与传输的分层判因

用于已有注册拒绝、挑战、凭证失效或协议成功却无业务效果的材料分析。只交付可复核事实和能区分假设的实验，不把单个 SDK 名、错误码或历史项目结论当通用归因。

## 先定位最后一个有证据的处理点

`DNS/路由 → TLS/QUIC → CDN/边缘 → 业务网关 → 请求/证明验证 → 设备与账号状态 → 业务提交 → 可见结果`

上述是分析层次，不是已发生流程。HTTP 200 可能来自边缘挑战；`code=0`、attestation 可解析、验证码完成或注册 SDK callback 都不能替代最终业务判官。

| 层次 | iOS 上要看的证据 | 不能推出 |
|---|---|---|
| 网络/握手 | URLSession/CFNetwork、Network.framework、自带 TLS、WKWebView 的真实执行路径与错误 | 有框架字符串就走该网络栈；timeout 就是风控 |
| ATS / 信任校验 | Info.plist 例外、证书链、主机名、SecTrust 或自定义校验调用 | ATS 配置等同所有自建网络代码都受约束 |
| Pinning / mTLS | 公钥/证书绑定，客户端 identity 选择、证书与私钥操作 | Pinning 与 mTLS 同方向；mTLS 成功就是账号授权 |
| TLS/H2/H3 特征 | 可见握手、JA3/JA4、ALPN、H2 设置/流控、QUIC、连接复用与重试 | JA4 相同等于同一设备或完整传输相同 |
| 请求签名/密文 | 原始 body 容器、顺序/重复键/编码、摘要覆盖、key/nonce/tag、绑定上下文 | 字段值相同就整个请求等价；高熵一定是加密 |
| 平台/密钥证明 | App Attest 验链/请求关联/counter、DeviceCheck 的实际消费、SecKey 属性 | 出现硬件 API 就证明当前请求被服务器认可 |
| 设备/账号状态 | 登记、凭证、刷新/撤销、登录状态、账号绑定 | 设备登记通过就能执行任意业务 |
| 行为/关联/业务 | 已观察遥测、频率、历史状态、服务端记录与可见效果 | 缺一条代理日志就缺上报；换号/IP 必能解决 |

TLS/H2 可观察信息依位置而异：客户端明文、CDN/TLS 终止点和普通旁路抓包不是同一视角。Network.framework、QUIC、后台 URLSession、扩展进程、WKWebView 与 native 自带网络库可能不被同一代理完整覆盖。Cookie/凭证共享也不能跨这些边界默认成立。

旧项目中抓到 `libboringssl` 不意味着所有业务流都由它承载。明确记录“未捕获”和“证据证明未发送”的区别。修改代理、ATS、禁 QUIC、杀进程或重启都改变了实验条件，不能为了抓到包先做再解释。

## 最小判因顺序

1. 汇总既有尝试的请求字节摘要、时间、目标版本、账号/session/设备脱敏标签、网络设置、响应和实际效果；跨脚本/工具合并计数。遇到“后端无记录”，先用已有材料核对查询标识及其映射、环境/租户、查询时间与异步提交/可见性窗口；未核对前仅记录“该查询未见记录”，不等同登记已拒绝。
2. 同一请求同字节总计最多 3 次，包含首次和已有尝试；有漂移提前停。第三次同类失败后不发第四枪，同一材料不可通过换工具重置预算。
3. 先核对已有原版成功与重构失败样本的 build、环境、账号/session、设备/密钥状态和材料时效是否可比；历史成功不能自动充当当前对照，不要求一次性 Challenge 相同。再做离线差分：前置 Challenge、设备/密钥登记、凭证、body 形态、遥测与响应。捕获覆盖未知时，不宣称完成全量 diff。
4. 留 2–3 个当前可区分的候选原因，每个配支持/反证、最小唯一变量、两种相反预期和停止条件。
5. 仅在当前授权、状态可控且确有必要时补采。一次性注册流程可使用授权的新鲜绑定材料作对照；旧票重放失败不能直接证明传输未打通。失败预算不是必须用尽三次。
6. 按证据牌照下结论。待验证轮换/冷却/原版对照只能写实验设计，不能当已经完成，也不自动切换账号、网络或设备。

如果当前任务仅本地分析、Skill 维护或取证设计，就停在现有材料与设计，不把“缺样本”转成真实注册、发码、登录或写 DeviceCheck 状态。

## 选一项能缩小缺口的实验

| 当前问题 | 优先本地材料或最窄补证 | 判断边界 |
|---|---|---|
| token 是透传还是派生 | 响应值→存储/读取→序列化/请求提交的字节关系 | 只知道响应出现它，不足以宣布客户端透传 |
| 注册 ID 稳定的原因 | 对照已有安装、IDFV、Keychain、keyID/公钥与服务器映射 | 一次重装值不变不能推出永久硬件 ID |
| 证明失败还是业务拒绝 | 分开验证 attestation/assertion、Challenge/counter 和服务器业务状态 | Apple 格式可解析或回调成功不证明业务放行 |
| 凭证过期还是错误绑定 | 签发/刷新时序、请求上下文和已有成功/失败样本 | 不猜 TTL；时间相关不等于已验证过期机制 |
| 漏遥测还是漏抓包 | 代码真实提交点与已捕获连接、扩展/后台任务对应 | 未知覆盖先保留，不盲补或重发遥测 |
| 传输差异还是字段/状态差异 | 原始请求、前置状态及可观测握手/H2/H3 档案 | 单个 JA4/UA 相等不是完整控制实验 |
| Hook 后异常是目标检测还是工具问题 | 原进程状态、工具链自证、最窄观测、具体崩溃/错误锚点 | 无 ObjC bridge、原生符号不存在等不能当反检测证据 |

服务端状态不可见时，明确“哪些候选尚不能区分”。风险模型可能结合设备、网络、账号关系、频率和行为序列，但不能编造模型权重、隐藏接口或数据库关系。VPN、共享出口、辅助功能或单个设备标签都不是恶意结论。

## 运行期取证边界

遵循 ios-dynamic 的本机工具事实：项目 venv、设备端 27045、无 ObjC bridge；可用原生导出/已验证符号或 ObjC runtime C API，不能照搬 `ObjC.classes` 脚本。

对已经运行且有登记状态的 App，先用已有日志与状态读证据，不为采样默认 spawn、清 Keychain、重装或批量生成 App Attest key。需要注入时固定进程身份和最窄边界，记录输入输出、异步关联、状态变化以及干预影响；不额外调用签名/证明函数凑样本。

私钥使用、私钥导出和远程证明是三个问题。硬件保护限制导出不代表不能调用签名；调用成功也不证明可离线复现或服务端消费了结果。
