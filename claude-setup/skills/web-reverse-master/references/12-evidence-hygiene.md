# Web 逆向证据卫生

在保存、共享或交付 HAR、HTTP 原文、Hook 日志、截图、PCAP、SourceMap 和 oracle 对拍结果时读取。目标是既保留可复核性，又不把凭据、PII 或无关数据扩散到文档和日志。

## 1. 原件与可分享副本分离

- 原始证据仅保存在任务授权范围内的受控目录，记录文件 hash、采集时间、目标版本、账号/会话代号和工具版本。
- 文档、报告和可分享夹带只引用脱敏副本；不要覆盖唯一原件。
- 每次转换记录 `original hash -> sanitized hash`、处理规则和操作者/脚本版本，使第三方能确认脱敏没有改变关键语义。

## 2. 必须脱敏

- `Cookie`/`Set-Cookie` 中的 session、refresh、CSRF 等可用值。
- `Authorization`、JWT、OAuth code/token、API key、签名密钥、客户端证书私钥。
- 密码、恢复码、验证码 ticket/validate 等仍可复用的凭证。
- 无关真实用户的姓名、邮箱、手机号、地址、账户 ID、头像和业务内容。

优先从采集源避免输出秘密；其次在结构化字段层替换为稳定占位符，例如 `<SESSION_A>`、`<TOKEN_1>`。不要只在截图上打码而保留同目录的明文 HAR。

## 3. 应保留的复核信息

- method、scheme/host/path、参数名、content-type、字段长度和编码层。
- request id、trace id、时间戳、GraphQL operation name、gRPC method、WebSocket message type。
- bundle URL/hash、脚本行号或 offset、initiator、调用栈、断点条件和工具版本。
- 响应状态、稳定业务码、必要的响应 shape，以及能证明状态变化的最小字段。

令牌值可以替换，但同一受控样本内的相等关系必须保留；如果两个字段原本相同，应使用同一个占位符。

## 4. 控制组与上下文边界

每项结论至少标明：

```text
baseline：原版或已知成功路径
variant：只改变一个变量的实验
same-run：是否同一版本、账号、会话、连接、IP/设备上下文
judge：字节 oracle、服务端业务语义或可见状态变化
```

不同会话、账号、版本或连接的材料不能直接拼成同一条因果链。需要跨上下文比较时，明确标注它只能说明相关性或绑定候选。

## 5. 结论分层

- **观察到**：请求/函数/帧确实出现。
- **格式闭合**：可以解析、编码或重建相同结构。
- **字节闭合**：同输入与 oracle 逐字节一致。
- **业务闭合**：真实下游接受并产生预期语义或状态变化。

低层证据不能冒充高层结论。HTTP 200、`101`、grpc-status、固定长度或无异常运行都不是业务闭合。

## 6. 重试与停止

同一请求同字节最多总计 3 次（含首次发送）。任一次出现响应漂移或随量降级，立即停止同字节重发并转环境/账号/IP/会话维度归因；3 次均恒拒也只说明当前请求未见随量漂移，随后转原版对照、全量流量 diff 或离线分析。

## 7. 交付前检查

- 原件、脱敏副本及 hash 映射齐全。
- 文档没有活凭据、私钥、真实用户 PII 或可直接重放的 Cookie。
- 关键 request/trace id、资产 hash、版本和时间仍可用于复核。
- baseline/variant/same-run/judge 完整，未把跨上下文材料拼接成成功链。
- 未解析字段、oracle、浏览器和工具依赖均已明示。
