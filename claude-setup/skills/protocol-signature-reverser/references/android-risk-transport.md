# Android 风控、传输与业务失败判因

用于已有失败响应、挑战、设备注册无效、签名通过但业务无效果等场景。目标是区分原因和证据缺口；不将厂商名、错误码、网络特征或单个风险标签当作最终原因。不预置指纹伪造、批量注册、换账号/IP 探测或在线兜底计划。

## 从到达层定位

先确认最后一个有证据的处理点，后续节点未知就保留未知：

`DNS/路由 → TLS/QUIC → CDN/边缘 → 业务网关 → 请求验证 → 设备/账号状态 → 业务提交 → 可见结果`

边缘可能返回 HTTP 200 的挑战页；业务网关也可能接受格式却拒绝提交。不能因为 JSON 可解析、TLS 成功或 `code=0` 就画出全部成功链。

| 层/候选 | 要检查的材料 | 不能直接推出 |
|---|---|---|
| DNS/网络/握手 | 原始错误、目标主机、证书链、ALPN、代理与网络库、连接时序 | 一次 timeout/403 就是某层风控 |
| TLS pinning / mTLS | Pin 校验点或客户端证书选择与私钥调用、握手证据 | 二者相同；握手成功即设备身份/账号可信 |
| TLS/HTTP/QUIC 特征 | ClientHello、JA3/JA4、H2 SETTINGS/流控、协议和连接复用；标观察位置 | 相同 JA4 就同设备/完整传输等价；不同指纹就恶意 |
| 请求签名/加密 | 完整原始字节、canonicalization、签名覆盖、key/nonce/tag、时间窗口 | 长 blob 必是加密；签名正确就可业务放行 |
| 平台/环境证明 | 具体 verdict、API 错误、请求绑定、版本及支持条件 | BASIC/已识别就是真人；UNEVALUATED 就作弊 |
| 设备注册状态 | 登记、持久化、刷新、撤销、密钥映射、前置 token | 拿到 device_id 就完成全部注册 |
| 账号/会话状态 | 登录状态、access/refresh 生命周期、Challenge、scope、绑定 | 设备凭证能替代账号授权 |
| 业务/行为/关联状态 | 完整可观测遥测、频率、事件顺序、历史风险、后端效果 | 原版成功自建失败只可能是签名或 TLS |

网络画像可能来自 OkHttp/Conscrypt、Cronet/BoringSSL、WebView、native 网络库或私有协议，按当前样本查证。换 User-Agent 不等于换网络栈；开启代理、禁 QUIC、重试与切换网络本身也会改变实验变量。

普通链路旁路观察无法直接读 TLS 内 HTTP/2 内容；CDN/TLS 终止点与客户端明文点有不同可见性。ECH、QUIC、后台连接、代理未覆盖的 native 栈都可能留下盲区。记录“哪个观察点看到了什么”，不要用抓包没出现断言接口未发生。

## 最小判因流程

1. 汇总已有尝试：请求字节摘要、设备/账号/session、IP/代理、时间、响应及业务结果。跨脚本尝试合并计数。
2. 停止条件优先：同字节含首次累计 3 次已用尽，或出现漂移/随量降级，不再发送相同请求；同接口同错误连续 3 次也停止同类尝试。
3. 先做本地差分：已捕获原版与重构请求、前置接口、遥测、凭证、时序、网络设置。缺样本只设计最小补采，不把“全量”写成已完成。
4. 保留 2–3 个可区分的假设：为每个写支持证据、反证、下一实验、预期相反结果与停止/恢复条件。
5. 新实验只在用户当前范围内进行；同环境原版对照也可能产生业务副作用，不能由“技能维护/本地梳理”自动授权。账号/IP/设备轮换和冷却复测依真实授权与时间执行，不模拟成已完成。
6. 对结论使用仓库证据牌照；证据不足交付未知与实验，不把统计相关写成绑定因果。

一次性 Challenge、平台 token、注册或交易请求可能不能安全重放；失败预算是上限，不是必须重试三次。并发操作可能污染计数器、风控历史和幂等状态，不并发探测来节省时间。

## 可选的区分实验

按当前缺口选一项，不按表全跑。带在线动作的设计不代表已经获准执行。

| 待区分问题 | 优先实验/材料 | 可证伪判据 |
|---|---|---|
| 本地生成还是上游透传 | 离线追响应字段→存储→请求构建；比较已有多次原始值 | 找到确定生产链；否则保持待定 |
| 请求签名还是会话令牌 | 精确输入链、既有不同 body/path 与同状态样本；必要时本地单变量 oracle | 覆盖字段与依赖可复核；不因两次相同就确定生命周期 |
| 凭证过期还是算法错误 | 已有成功/失败样本时间、签发/刷新记录、服务端明确语义 | 仅凭时间相关不足；需要刷新或状态对照证据 |
| 注册未完成还是权限不足 | 分开核验设备登记、密钥登记、账号绑定、业务提交的输出与消费者 | 每个阶段对应独立判官，不越级宣告成功 |
| 遥测缺失还是抓包盲区 | 确认网络栈与观察覆盖，关联本地事件调用和已有服务端日志 | 没有发送证据与没有抓到必须分开 |
| 传输差异还是业务状态差异 | 先原始请求/前置状态 diff，再比可观测握手和 HTTP 特征 | 单个 JA4 相等或一个 Header 相同不构成控制实验 |
| Root/Hook 标签还是实际拒绝原因 | 原环境基线、工具链自证、最窄无改写观测和具体错误分支 | 标签存在不证明被消费，更不证明最终拒绝因果 |

## 风控结果分开记录

按实际响应记录：允许、交互挑战、二次认证、限额/延迟、拒绝、未知；验证码完成或 SDK callback 成功不等于业务授权。

设备指纹、IP/ASN、账号关系、频率和行为序列可以是评分输入。VPN、共享出口、辅助功能、旧补丁或大量设备属性相同都有正常场景；不把单一信号写成必然恶意。

短期风险 token 可能只承载当时状态，可能绑定版本、请求、会话或设备。只有有证据才填写 TTL 和刷新规则。若服务端代码不可见，不能凭 token 外观编造评分模型、权重或隐藏数据库关系。

使用 [共同报告模板](../assets/device-enrollment-audit.md) 的分层结果和实验表，保留未解析字段、未覆盖流量和真实业务判官。不能从“只有在线平台能签发”跳到“所有相关算法都不可还原”；按字段拆出可本地复现部分与外部依赖，主 Skill 的止损决议要求仍适用。
