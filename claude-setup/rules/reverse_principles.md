## 0. 适用范围（先分层，防本文件自身模板化）

## 序言（唯一的哲学，到此为止）

目标开工前定死，不可漂移；路径按缺口选，对方法零忠诚；
一切"找不到"的归因来自实验，不来自叙事；**把没找到的当找到了的交付是唯一死罪**。

## 1. 开工检查（攻坚任务 6 项，缺一禁开工）

## 2. 路径选择（成本参考序 + 缺口驱动，不是流水线）

- 成本序（低→高）：查memory已知 > 识别已知产品(壳/SDK指纹) > Java层 > SO静态 > 定点hook > unidbg > 真机oracle > 在线兜底
- 选择规则：先判断**缺口在哪一层**，直接从该层进入；多条路能闭合同一缺口 → 选成本序更靠左的；**禁止逐级通关式推进**（那是模板）。
- 时序铁律：止损决议之前，兜底不得出现在任何计划里；止损决议必须附"已穷尽假设清单"，否则无效。

## 3. 归因程序（失败时按序执行，每步是实验，不是猜测）

1. **同一请求同字节最多总计3次（含首次发送）**：任一次出现漂移/随量降级 → 有状态计分（风控方向），立即停止同字节重发并转 4、5；若3次均恒定拒绝，只证明“当前请求未见随量漂移”（**≠算法错 / 无记忆校验**），立即停止线上实验并转 2、3、4
2. **原版App同环境对照**：原版也挂 → 环境已烧（或服务端故障，换无关接口验证）；原版过我不过 → 缺口在我
3. **全量流量diff**（含埋点/上报）：差集 = 行为域缺块 TODO 清单
4. **维度轮换**（换IP/账号/设备）：哪个救活，分记哪维
5. **冷却24-48h自愈** → 计分衰减，风控实锤
6. 以上全排除 → 物理持有 → 转oracle/魔改（**此刻才是合法止损点**）

## 4. 禁词牌照表（全局生效）

| 禁词 | 解锁牌照 |
|------|----------|
| "被风控了" | 两证：原版同环境对照也挂 +（维度轮换定位 或 冷却自愈） |
| "有反调试/反Frida" | 两证：工具链自证正常(对已知无防护App可attach) + 目标App上失败可复现 |

| "已还原/纯算完成" | 参数谱系零空洞 + ≥3组任意输入oracle对拍一致 + 动态字段单变量实验全部落定 |

- 元规则：**任何足以终结调查的结论都需牌照**；词表开放追加。
- 每轮合法产出仅两种：带证据锚点的结论 / 下一个区分性实验设计。**假设不配作为交付物**。

## 5. 交付检查（四件套：谱×物×证×界，缺项禁交付）

### 谱——参数谱系表（逆向交付的核心，防字段级造假）

交付链路中**每个字段一行**（headers/query/body/嵌套密钥/常量）：

| 字段 | 来源 | 生成算法 | 生命周期与绑定 | 单变量验证 |
|------|------|----------|----------------|------------|
| token | 服务端下发 | 登录接口 resp.j.token | 7d TTL，/api/refresh 刷新 | 过期→401，刷新后通 |
| x-s | 本地生成 | HMAC-SHA256(k1, sorted(qs)+md5(body)) | 单次 | 对拍一致；改1字符→拒 |
| deviceId | 设备态 | 首启UUIDv4存/data/prefs | 永久/设备绑定 | 换值→风控评分变化 |

- 来源四选一：静态常量(值+提取处) / 本地生成(算法+输入) / 服务端下发(接口+刷新方式) / 派生(依赖字段+计算式)
- 来源判定铁律：先分清"要还原的算法"与"上游透传值"——很多看着加密的字段其实是上游接口下发的透传值，别当算法硬撕（①纯算/②设备指纹/③透传 三分类与软硬件分界详见 `~/.claude/reverse_signature_principles.md`）
- [ ] 谱系零空洞：每行五列填实，验证列来自实验不是推断
- [ ] 任意输入对拍：≥3组非样例输入与真机oracle逐字节一致（防样例拟合）
- [ ] 脚本=谱系的实体化：字段↔生成函数一一对应
- [ ] 硬编码动态字段=造假：抓包来的值必须标注"重放值+时效炸弹"
- [ ] 隐式oracle必须明示：脚本内部向真机/原App取任何值→标注oracle依赖，禁止宣称纯协议

### 物（正常工程基线）

- [ ] 可运行
- [ ] 自包含交付：运行所需一切（代码/脚本/依赖/文档/样例）落在交付目录内，不依赖仓库外散落文件——Android 目标用 projects/<target>/ 模板，Web/iOS 等按各自项目结构，要求的是自包含不是具体目录名
- [ ] README 含入口/依赖/用法
- [ ] 换人换机可复现

### 证（判官验收）

- [ ] 判官验收通过（域相关：服务端语义 / jadx完整反编译 / 向量对拍）
- [ ] e2e 证据留存
- [ ] 持续批量类加做：重复成功率 + 新会话冷启动 + 24-48h延迟复查

### 界（边界声明）

- [ ] 版本锚点（app版本/SO hash/设备型号）
- [ ] 工作条件（IP策略/频率上限/账号要求）
- [ ] 失效表现（升级后什么症状）
- [ ] 未逆清单（**字段粒度**）

### 交付形态三级（全部合法，唯一非法的是伪装）

1. **解析型(纯算)**：谱系零空洞——**唯一配称"还原完成"的形态**
2. **绕过型**：依赖条件成立（如服务端只在缺header时校验）——可交付能力，必须标注依赖条件与脆弱性，不得称还原完成
3. **止损型(oracle/兜底)**：未解析字段全部列明，明示运行依赖

## 6. 环境红线（全局生效）

- 禁批量发无效签名；单IP禁碰多号；验证期单设备单账号
- 同一请求同字节最多总计3次（含首次发送）；第3次同类失败立即停止线上实验 → 走 §3 的原版对照、全量流量diff或维度轮换
- 侵入度就低不就高：零注入 > attach > spawn > 重打包

## 7. 留痕（全局生效）

- 成败皆记 `.zcode/memory/<target>_<topic>.md` 并回写 MEMORY.md 索引
- 止损三要素：未解缺口 + 当时假设 + 停手理由；**禁写"XX有墙"**
- 未解析字段即字段级的"没找到"：任何交付里的黑盒字段必须显形
