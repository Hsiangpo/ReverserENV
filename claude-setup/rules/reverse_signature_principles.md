# 逆向总原则：签名/加密参数的可离线性判定（全局，适用于所有逆向项目）

拆签名、还原加密参数前先套这套心法。核心结论：**绝大多数客户端签名都能"纯协议"还原**，只有一个很窄的硬件例外。别一上来就断定"算不出/不可还原"，也别用"一定能"绑架自己死磕。

## 1. 先给每个"加密/动态参数"定来源（三分类）

请求里每个看起来加密/动态的字段，先归到三类之一：

- **① 客户端纯算**：HMAC / MD5 / SHA / AES / RSA / 自定义白盒 / GF变换 / VMP… 算法就在客户端二进制里。→ 原理上一定可复现。
- **② 可采设备指纹**：device_id / OAID / drm_id / MAC / 传感器指纹 / 各种硬件编号… → 一次性从真机采集，喂进算法（"硬补指纹"）。
- **③ 服务器下发的透传值**：token / xid / dfp_id / sessionId / ticket / nonce / salt / 公钥 / cookie… 很多"看着加密"的值其实是**上游接口请求由服务器下发**的，客户端只是**原样透传**，根本不用还原它的算法。→ 先打上游接口拿到再喂进去；注意**时效**（过期要刷新）。

> 铁律：**别把 ③ 的透传值误当成 ① 要还原的算法**——先分清 ①②③ 能省掉大量白盒硬撕。

## 2. "纯离线" = "纯协议"（定义，别抠字眼）

纯离线 = 运行时**不依赖真机/模拟器**，所有输入靠：协议请求拿（含先打上游接口拿 cookie/response 里的下发值 → 喂给下游签名）**或** 一次性静态提取（指纹/密钥）。**打上游接口拿 token 再传下游，本身就是协议链的一环，不算"依赖设备"。** 强时效签名允许"离线主体 + 在线兜底取那几个下发值"的混合，仍算纯协议。

## 3. 判据：能生成 ⇒ 原理上可复现（但要分档判工作量）

**客户端自己能生成的签名，原理上一定可还原**——代码在你手里、确定性执行；纯软件最差用**全模拟**（unidbg / unicorn / 符号执行）也一定能跑出结果。所以：

- VMP / 重白盒 / 深度 OLLVM = **时间问题（长周期），不是可行性问题**。**一旦定了硬啃，就持续推进到把整套 VM 完整还原**（dispatcher/handler 表 + 字节码 → 逐 opcode 语义化，全 devirtualize），别半途而废、别做半吊子。手法：unidbg/unicorn 全指令 trace 抓真实执行路（天然反平坦化）→ D-810/去平坦化 → 逐 handler 语义还原，分阶段收敛。**这类是耗时不是卡死，不算 §6 的止损项**——用户要硬啃就一直干到还原完为止。
- 卡住时**几乎从不是"算不出"，而是缺输入**：缺 ③ 上游下发值 → 补对应接口；缺 ② 设备指纹 → 采那一项。先补输入，别先怀疑算法不可逆。
- 算法本身撕不动时，用 unidbg 跑真 .so / Frida oracle 兜底，同样算"本地可生成"。

## 4. 设备绑定：分清两个东西（这是唯一真墙所在）

- **(A) 服务器下发的设备注册令牌**（dfp_id / device_id / xid）：**是注册接口返回的数据**，可重放可复现。**采设备标识 → 打注册接口 → 拿令牌 → 复现签名**。这是"设备绑定"的 **99%**，纯协议完全搞定（XHS 改机批量号即此路）。
- **(B) 不可导出硬件密钥的私钥**（StrongBox/Titan、SE、苹果 SEP、正经 TrustZone）：**不是接口下发的**，是安全芯片用硬件 RNG **当场随机生成**、永不出芯片；**跟设备编号无函数关系，采再多标识也拼不出**。只有公钥/attestation 证书出来；服务器靠**厂商预置、Google 签名的 attestation 证书链**信任它，软件造的假 key **attestation 造不出来**。

**唯一"采标识+注册"也没用的墙** = 服务器**强制硬件 attestation / 每请求 SE 现场签**：Play Integrity 强校验、FIDO/passkey、支付 tokenization、Widevine L1 DRM。**且这在普通请求签名里极少见**（硬件密钥太重、要求有 SE、跨设备不通用，没人拿它签普通反爬请求）。
实战里就算遇到 attestation，破法也常是"服务器没严格校验 / 目标接口没 gate 在 attestation 上"→ 绕回协议层；或走特定芯片 TEE 漏洞抠 keymaster 私钥（另一条硬啃路，非采标识）。

## 5. 怎么一眼分清"软件可提" vs "硬件绑定"

- 内存/文件能找到密钥字节，或算法带常量表（S盒/T表/魔数）→ **软件，可提可纯算** ✅
- 走 Android Keystore alias、只调 keymaster/keystore 现场出签名、带 StrongBox/attestation、dump 不到密钥 → **硬件绑定，只能设备 oracle** ⚠️
- unidbg 离线试跑：缺一个没法伪造的 keystore syscall/HAL 调用才卡死 = 硬件；能靠喂状态跑通 = 软件。

## 6. 止损线 & 风控红线

- **真止损（采标识 + 硬啃都没用）= 只有 (B) 硬件 attestation / SE 每请求现场签** → 转设备 oracle / 混合，别用"一定能纯算"死磕。
- **强时效生命周期绑定**：算得出但必须新鲜/在线 → "离线主体 + 在线兜底取那几个下发值"混合（是方案形态，不是放弃）。
- **VMP / 重白盒 ≠ 止损**：是长周期硬啃。**用户一旦选择硬啃，就持续推进直到整套 VM 完整还原（见 §3），不半途转向、不当墙放弃**。
- **验证自造签名 e2e（注入真 App 请求看 code=0）时绝不高频重试无效签名** → 会触发服务端风控**软封整设备**（Keeta 实测：连续 403 → App「網路連線異常」，连自身合法签名也被封，重启无效）。做法：**单次 / 用当前有效令牌 / 限一个非关键端点 / 间隔久 / 先存一份 code=0 基线对照 / 连续失败立即停手**。
